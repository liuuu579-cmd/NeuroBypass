# 逐样本贪心参考实验

本轮先检验输入相关剪枝的可利用空间，再决定是否扩大 Router 训练。所有旧源程序、数据和结果保持原样。新增程序为 `tools/stage2_greedy_reference_v1.py`，正式运行目录为 `runs/stage2_greedy_20261103_01/`。

## 预先固定的比较

- 模型：本地 OPT-13B，FP16、SDPA，关闭 KV cache。剪层直接绕过 decoder layer，保护第 0、1 层。
- 输入：上一阶段 256 个 C4 测试 token 块中，用 seed 579 无放回抽取 32 块，每块 256 token。抽样和方案交换映射在搜索前写入 `experiment.json`。
- 每个输入分别按 `last_token` KL 和 `all_tokens` 平均 KL 搜索。从空剪枝集合开始，每一步遍历所有未剪且可剪的层，加入目标 KL 最小的层，直到剪掉 16 层；记录 K=6、16 的完整质量指标。
- 静态对照沿用上一阶段仅由 8 个校准块得到的固定贪心路径，不使用这 32 块重新校准。
- 输入匹配对照：用 seed 580 产生无固定点的循环置换，让每个输入使用另一个输入的搜索方案。每个方案在对照中恰好使用一次，方案的边际分布不变。该对照回答方案与具体输入匹配的价值。
- 指标：最后一个 token 的 teacher KL、全部 token 的 teacher KL、255 个真实后续 token 的 NLL，以及总体 `exp(mean NLL)` 得到的 PPL。KL 方向统一为完整模型到剪枝模型。
- 对每种目标、K 和指标，计算匹配搜索相对静态、相对交换方案的逐块差值，按块做 10,000 次配对 bootstrap，报告描述性 95% 区间。

## 资源和证据

通过 `tools/run_with_resources_v2.py --gpus 1,3` 启动：两张物理 GPU、整个进程树共 21 个物理 CPU 核（0–20），每个 worker 的 PyTorch 线程数为 10。资源入口的父子进程继承 CPU affinity。预检运行 `runs/stage2_preflight_20261103_01/` 的三项测试全部通过，覆盖目标计算、单步候选选择、配对顺序和无固定点交换。

正式运行应产生 64 条搜索路径、1,024 个搜索步骤、31,232 次候选评分，以及 352 条质量记录。`greedy_search_steps.jsonl` 保留每个候选分数和次优差距；`greedy_paths.jsonl` 保留每条路径；`sample_metrics.jsonl` 和 `summary.json` 保留质量与配对比较。完成后必须复算同一输入的完整模型和静态方案，确认与上一阶段一致。

`analysis/stage2_start_baseline_20261103.json` 记录本轮开始前 175 个已有文件的 SHA256。结束后同时核对这些文件与 `analysis/source_manifest.json` 中原始文件、归档副本的哈希。仅上传新增代码、协议、日志和指标，不上传 token 数组、语料或权重。

## 结论边界

这里搜索时可以调用完整模型，并且在当前输入上选方案、评估方案。因此它只是昂贵的质量参考，不能部署为便宜 Router，也不能证明泛化能力、全局最优或一个严格质量上界。贪心路径可能错过更好的联合剪层组合。

32 个样本的单位是 token 块，文档独立性尚未确认。块 bootstrap 没有解决文档依赖或多重比较问题。样本来自上一阶段的评估池，本轮用于研究决策，后续正式泛化评测仍需新的文档分组测试集。报告不把 KL、PPL 改善直接解释为下游任务准确率或实测推理加速。
