# 下一阶段：冻结现有模型进行横向比较

## 决策与当前状态

可以进入横向比较。用户接受当前约 0.08 的 KL 量级，接下来优先测量下游任务质量和实际运行成本，不把继续压低开发集 KL 设为前置条件。KL 本身没有通用的可接受阈值；任务准确率、困惑度和耗时共同决定实用性。

本文是新增的评测准备方案，尚未实现新评测适配器或启动横向 GPU 实验。下列方法和数据可用性核对不等同于完整基准已经可运行。已有程序、权重、输入数据和结果均保持原样。

## 冻结参评模型与共同条件

共同基座为本地 OPT-13B、FP16，同一 tokenizer。首轮固定跳过 6/40 层，保护层 0、1，不做恢复训练，不按新任务结果重新选择模型或剪层方案。

主动态方案采用阶段4已选定的分类目标分叉 Router：`runs/stage4_branch_main_20261105_01/private_augmented_epoch_004.pth`，SHA256 为 `8e73232cd8a6c89291c56bd8d2b5cc05e2a00c1d36977c79036e74641229b5fa`。本轮准备时实际核对了该哈希。原选择32文档 KL=0.078923，全部100个开发验证文档 KL=0.086419；二者不能混用。阶段5分类组三个种子作为复现补充，不根据新任务分数选出最好的种子；排序组不替换主方案。

| 参评项 | 用途与条件 |
| --- | --- |
| 完整 OPT-13B | 质量与运行成本参照，K=0 |
| 当前每轮提示词固定动态 Router | 主方案，K=6；保持联合贪心选择，不改成独立逐层选择 |
| 同800训练文档学习的静态方案 | 强内部对照，固定跳层集合 `{2,4,8,10,14,16}`；其原开发100文档 KL=0.081695 |
| 现有校准静态贪心 | 保留原先基线，单独标注较小校准数据预算 |
| ShortGPT 式 block influence 静态剪层 | 外部方法候选；先核对原论文/官方实现、校准规则与 OPT 适配，再锁定实现和来源版本。自实现适配必须明确标注，不能冒称官方复现 |
| 固定种子随机静态集合 | 低成本参照；保护范围和K一致，预先固定种子，不搜索后取最优 |

ShortenedLLaMA 作为后续恢复训练比较候选：先核实具体方法版本、模型适配和训练设置。若包含恢复微调，动态和静态双方都应获得明确匹配的恢复训练预算，分别报告剪后直接评测与恢复后评测。不同基座、数据、剪层比例或训练预算的论文表格不能直接并入本次同模型比较。

## 下游质量评测

首轮采用零样本 PIQA、HellaSwag、WinoGrande，并补充 WikiText-2 语言建模评测。准备时只读核对了本地 Arrow 数据：PIQA validation 1838条，HellaSwag validation 10042条，WinoGrande validation 1267条，WikiText-2 test 4358个文本行。文本行数不是有效 token 数或独立文档数。任务使用公开有标签的 split，并如实称为 benchmark validation，不能混称私有 test。

本地存在 `skip/lm-evaluation-harness`；其当前任务配置的数据集标识与部分历史缓存并不相同，WikiText 配置还要求 document-level 数据。正式运行前须固定框架版本、任务模板、数据指纹、分词、截断和答案打分口径，使用新程序做缓存适配。缓存存在不代表现有任务入口已经全部通过。

- 多选任务按固定模板报告 accuracy，并在适用时同时报告 length-normalized accuracy，不能逐方法选最有利指标。先记录完整模型基准以发现数据或打分错误。
- 每道题仅根据共同题干、不含候选答案及正确标签的信息选一次路由，所有候选答案复用该方案。不能把“题干+候选答案”分别送入 Router 后变成不同方案，也不能据答案重选方案。WinoGrande 的填空模板需专门审计。
- Router 特征沿用训练时的提示词 embedding 定义与最多128 token 的输入范围；完整模型的任务上下文不据此一律截断为128。短提示词、padding 和 batch 的处理须在适配器中明确，避免填充改变路由。路由一次后，本题 prefill、候选打分或生成保持固定方案。
- 对语言建模，先以128-token前缀选层，再只对其后的目标 token 计算条件续写 NLL/PPL；所有方法使用相同前缀、目标范围与 token 加权规则。不得用一段文本的未来目标 token 选路由，再回头给这些 token 评分。
- 上述条件续写 PPL 须单独命名和完整说明，不能直接叫标准全量 WikiText-2 PPL。若另做标准 rolling PPL，需新增经审计的因果路由协议并单列结果，不能与条件续写 PPL 或论文数字混用。
- 保存逐题正确性、逐记录 NLL/有效token数和路由集合，按题目/文档配对统计方法差异与区间。三个训练种子仍是同一批题目的重复评价，不是三倍独立样本。
- 新任务用于冻结方案的外部评估；不使用其正确标签校准静态方案、选择checkpoint或调损失。旧C4测试结果保持原样，不把重复评测称为新独立证据。历史数据与近重复的局限继续如实说明。

## 实际成本比较

质量比较与运行计时分别执行。计时在同一张物理卡上依次、交错重复各方案，固定精度、attention实现、输入长度、batch和生成长度，显式CUDA同步并预热；不把两张不同卡同时运行的方法直接相除当加速比。记录输入长度128/512/1024、batch1、固定生成128 token，至少5次预热和20次测量，忽略EOS提前停止；其他吞吐场景另外注明。

分别报告 Router耗时、prefill、首token延迟、decode tokens/s、总耗时、峰值显存和KV张量实际字节数，动态总耗时包含路由开销。每轮固定路由，新一轮变更路由须重建整个上下文KV；另外测量一次换轮重建成本，不把历史缓存免费复用。

动态方案当前保留完整模型权重，跳6层只直接减少相应计算和KV，不能宣称权重显存也压缩15%。静态方法除统一的真实绕层模式外，应补充物理删除层后的部署模式；先验证两种静态实现的质量/输出一致性，再比较权重常驻与峰值显存。不能强迫静态保留多余权重从而掩盖其部署优势。

## 执行顺序与资源

1. 只新增独立评测程序，冻结任务模板、数据指纹、模型哈希和外部方法来源；在非正式子集做流程审计，不据其准确率调整模型。
2. 用完整模型和固定路由先检查答案打分、无未来信息泄漏、真实跳层以及缓存一致性，再运行冻结模型的完整任务比较。
3. 单独测量速度/显存，生成同一基座、同一K的质量—成本表，并保留全部种子及逐题结果。
4. 基于完整横向结果决定是否值得恢复微调、扩大训练数据或研究自适应K。首轮不把训练支持范围之外的K混入当前模型结论。

所有GPU任务继续通过 `tools/run_with_resources_v2.py`，2 GPU对应整个实验进程树21个CPU核。数据并行质量评测可使用两卡；同卡顺序计时若单独申请1卡，则相应限制为10核。运行使用全新目录，发布新增源代码、协议和不含原始语料/token序列/权重的汇总与记录。
