# 全部 token 目标的静态对照补充

逐输入参考完成后，发现原静态方案使用最后一个 token 校准，不能单凭它与全部 token 搜索的差距区分“目标改进”和“输入选择改进”。因此追加同目标静态对照，程序为新增的 `tools/stage2_static_all_tokens_v1.py`。这是在查看逐输入实验后追加的分析，不属于原先预先固定的比较。

静态方案只用原阶段 1 的 8 个校准块，在层 2–39 上贪心搜索 16 步，目标为全部 token 的完整模型到剪枝模型平均 KL。两个 worker 按候选层分片，各自读取同一校准集。所有逐步候选分数和固定路径均保留。

固定方案生成后，按 K=6、16 评估原先的 256 个测试块。报告分别给出完整 256 块与阶段 2 同一 32 块子集的结果；只有 32 块子集与逐输入搜索做配对比较。使用完整模型 teacher 分布评分，静态路径选择阶段不读取测试块。资源仍为 GPU 1、3 与整个进程树 21 核，不与原阶段 2 并发。

这个静态基线仍只有 8 个校准块，贪心也不能保证全局最优。当前结论是相对这两个具体静态方案的结果，不代表打败所有静态剪枝方法。
