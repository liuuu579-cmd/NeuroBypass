# 阶段4：联合贪心分叉状态实验协议

目标是检验：增加已剪集合的覆盖，能否改善后期候选层排序，并建立对真实提示词的匹配收益。保留原源文件、旧报告、旧checkpoint与token数组；实现只新增独立程序。

## 数据与标签

- 使用阶段3原800条训练记录；不把任何验证/测试扫描结果加入训练标签。
- 原100条验证记录保持开发用途；原32条用于选checkpoint，另外68条单独报告，不能称为新独立测试。
- 输入128-token提示词embedding；离线联合KL目标为后续32-token续写。OPT-13B冻结，保护0、1层，固定跳6层。
- 每条训练记录观察旧Router前3层集合。若它与正确贪心集合不同，则从自身集合继续；否则保留贪心前2层，将第三层替换为该步联合候选排序第2至5名之一，按seed579及sample编号确定。
- 从该3层集合出发，对第4、5、6步分别完整枚举剩余层，每次选择整个已有集合加候选后的续写KL最低者。候选数依次35、34、33，每文档102次评分，总81600次；与同文档旧状态完全重合时可复用评分。
- 因旧Router在训练样本上大多复现正确路径，强制分叉用于保证存在不同初始集合。本轮是固定旧行为模型的离线状态扩充，不是在线迭代DAgger。

## 匹配对照

| 项目 | 基线组 | 分叉组 |
| --- | --- | --- |
| 文档 | 同800条 | 同800条 |
| 每文档9个状态槽位 | 原6步+重复原4至6步 | 原6步+分叉4至6步 |
| 参数/初始化 | 原宽256 Router，seed579 | 相同 |
| 编码/样本顺序 | 每batch只编码一次提示词 | 相同 |
| 预算 | batch16，50步/epoch，24epoch，共1200次更新 | 相同 |
| 目标 | 软CE+0.25硬CE，原温度规则 | 相同 |
| 优化器 | AdamW lr2e-4、weight_decay0.01、5%warmup后cosine、clip1 | 相同 |

使用重复后期状态的基线控制后期权重，避免新增状态同时增加更新次数的混淆。因此它与阶段3原六状态训练有所不同，主要比较本次两组。

按原32条验证记录的真实续写KL在epoch1、4、8、12、16、20、24选checkpoint。每组最终在100条验证记录上报告真实方案、4次交换方案、旧16条校准静态、800条训练得到的固定输入静态、完整OPT和逐样本贪心诊断值。

主要看分叉组相对匹配基线的配对KL差，以及分叉组相对交换方案、学习静态的差。交换对照先在每个目标文档内平均四次，再做10000次文档配对bootstrap；四次置换不增加独立样本数。区间为描述性结果，不校正文档依赖与多重比较。

## 执行与验收

生产入口为`tools/train_augmented_router_v2.py`；v1为未执行草稿。`tools/test_augmented_router_v1.py`检查分叉、候选集合、状态配额和配对算术。四条文档的两卡探针会跑通标签、两组训练和验证，并检查缓存等价性；探针不提供研究结论。

正式使用物理GPU1、3，整个实验进程树CPU0至20共21核，每worker10线程，统一经`tools/run_with_resources_v2.py`。预计标签生成约35分钟，实际依服务器负载变化。

有限本地控制程序`tools/run_branch_pipeline_v1.py`顺序运行：标签生成、两组训练、开发验证、独立核验、新报告/CSV及GitHub新增文件发布。核验失败不发布成功报告。没有重复定时任务，也不向他人发送消息。

核验包括800文档/2400状态/81600候选评分、训练与验证分组、同初始化/容量/更新次数/后期权重、原文件哈希、旧checkpoint和输入数组哈希。权重、语料、原始token数组和生成序列只留本地。

## 结论边界

单种子、固定K、C4自然续写及历史近重复限制不变。贪心oracle使用了真实续写，不保证全局最优，也不全是提示词可预测的信息；不据其差距直接宣称路由器可恢复到该质量。本轮不额外宣称加速，不做双方恢复微调。若状态覆盖仍不产生稳定改善，下一个独立控制变量是候选联合KL差的排序目标。
