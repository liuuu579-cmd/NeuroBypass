# 横向质量结果后的吞吐量与峰值显存协议

阶段7已完成并验收514041条评分，运行3.56小时。原流水线最后因上传约69MiB的逐题JSONL网络失败而报错；质量计算、CPU验收、CSV及报告均完成。汇总发布已另行恢复，大型逐题文件完整保存在本地。K=10混合方案在四项指标的点估计均优于SLEB适配；K=12/16各有三项更好，不能称为所有任务显著领先。静态联合贪心仍为强基线，混合方案与它互有胜负。

按用户授权进入成本测量。本轮工作点为K=10、12；不是再次训练或根据新任务重选种子。完整OPT-13B、静态联合KL、SLEB适配、混合各三个已有种子均保留。静态方法分别测完整权重常驻下真实跳层和物理删层部署，共15个配置。

每卡独立比较所有配置，绝不拿不同卡的方法耗时直接相除。GPU0/1/2分别测试输入128/512/1024，第4卡独立重复512以保留跨卡变化证据。所有请求batch1、FP16/SDPA，生成固定128token、忽略EOS。每配置5次预热、20次正式测量，每轮同一输入、随机交错配置顺序。动态路由仅观察提示词前最多128token，整个请求固定路径，计入一次路由开销。各卡有自己的完整模型基准。

分别报告路由、prefill、首token时间、后续127token decode吞吐、含首token的端到端吞吐、总耗时及P95。显式CUDA同步划分计时段。这里使用正常OPT CausalLM的完整序列prefill输出头，不据此次结果声称达到优化服务框架的吞吐。

每请求开始清理空闲allocator块，记录PyTorch peak allocated与reserved、模型/路由器CUDA参数字节、KV实际张量字节；不冒称整进程NVML峰值。物理删层版本从decoder ModuleList和GPU中移除剪掉的层，重编缓存索引，只为下一配置恢复而保留CPU副本。权重布局切换是部署准备，不计入稳态请求时间。物理删层与原索引真实跳层必须通过缓存logits与生成token哈希一致性验收。

运行前对全部参评路径检查FP16 cached/full分布差异，沿用mean KL<=1e-4、max KL<=1e-3，不通过就保留失败证据、暂停正式计时并诊断。探针不证明所有输入路径都稳定。每请求新建cache，检查各层cache长度和实际字节；改变已有cache路径必须报错。新对话回合换路由需把完整累积历史重建，这些长度的prefill包含重建计算，但本轮不单列旧cache释放或真实服务调度成本。

仅使用原训练记录组成计时输入，同一轮各方法用相同内容；不把计时输入当作新增质量证据。三训练种子单列，不择优，也不混为额外独立题目。独立CPU验收重新检查行数、计时分解、token数、KV字节、部署权重变化及静态输出一致性。
