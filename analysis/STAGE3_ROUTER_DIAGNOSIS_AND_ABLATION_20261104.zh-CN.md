# Router 泛化诊断与小容量输入消融

本轮完成两项实验：冻结原 Router 的路径/输入诊断，以及同容量“真实提示词 / 固定输入”两组训练。结论是：当前主要瓶颈是输入相关选层的泛化；仅缩小 Router 未解决问题。前期相对16条校准静态基线的收益，不能直接作为动态匹配有效的证据。

全部新增独立程序和结果目录；OPT权重冻结。当前实验未使用旧测试集做训练、选checkpoint或追加评估。

## 评估边界

- 800条训练、100条验证保持不变。验证集已用于开发诊断，不能当作新独立测试集。
- 原32条验证记录继续用于选checkpoint；另外68条仅表示未参与checkpoint选择，本轮诊断已检查过它们。
- 数据仍为128-token提示词后的32-token C4自然续写，不是聊天或下游任务。历史近重复与数据来源限制仍适用。
- 以下KL均相对完整OPT的输出分布，越低越好。训练样本结果只用于诊断。

## 原 Router：训练样本拟合充分，但输入匹配收益未泛化

| 方案 | 64条训练诊断 KL | 100条验证 KL |
| --- | ---: | ---: |
| 逐样本条件贪心搜索 | 0.052840 | 0.053710 |
| 原宽256 Router | 0.052910 | 0.089959 |
| 交换输入的方案，4次置换平均 | 0.097251 | 0.091001 |
| 旧16条校准静态方案 | 0.103439 | 0.099735 |

验证集真实输入减交换方案的平均KL差为-0.001042，95%配对bootstrap区间[-0.007207, 0.005406]，仍包含0。四次置换不是400条独立样本，先对每个目标记录平均，再按100条记录配对统计。

原Router在训练诊断集几乎追平离线贪心搜索，验证集却保留明显差距，符合训练拟合很强而泛化不足的表现。离线搜索看到了真实续写，其性能不是仅观察提示词的Router必然可达到的上限；贪心也不保证全局最优。

在正确贪心集合条件下，各步选中最低KL候选层的比例：

| 选层步数 | 训练800条 top1 | 验证100条 top1 | 验证候选排序平均名次 | 验证额外KL |
| ---: | ---: | ---: | ---: | ---: |
| 1 | 96.9% | 25.0% | 3.09 | 0.001080 |
| 2 | 98.1% | 19.0% | 5.21 | 0.003241 |
| 3 | 97.2% | 18.0% | 6.91 | 0.006224 |
| 4 | 94.0% | 17.0% | 7.11 | 0.007732 |
| 5 | 89.9% | 10.0% | 9.29 | 0.015514 |
| 6 | 94.9% | 14.0% | 9.97 | 0.023287 |

额外KL表示同一已有剪层集合下，“Router选择候选的联合KL”减去“最低候选联合KL”，不是单层独立损失。后期即使给正确前缀也排序不佳，说明不能只把问题归因于自回归选层时的路径偏离。

## 自身路径与协同误差

在16条未参与checkpoint选择的验证记录上，完整枚举Router自身路径每一步的剩余候选层。验证了96个状态、3408个候选评分，其中2548次为新增模型前向，其余复用了相同集合下的旧评分。

| 方案 | 16条记录平均KL |
| --- | ---: |
| 原Router | 0.082835 |
| 完整条件贪心路径 | 0.049551 |
| 保留Router前5层选择，仅离线修正最后一层 | 0.054248 |
| 提供贪心前5层，最后一层由Router选 | 0.068976 |

最后一步仍有较大可修正损失，支持优先改善联合候选排序和后期组合覆盖。但上述修正使用真实续写，只是离线诊断，不能用作线上路由。

进入第6步时，验证样本的Router前缀集合有37%未在训练贪心轨迹出现；验证样本自己的正确贪心前缀则有60%未出现。集合是否见过只是覆盖统计，不足以单独证明路径偏离的因果作用。

训练软标签每步约有16至17个有效候选，最优候选平均概率约10%至18%。标签较平，但还叠加0.25权重的硬选择损失；目前不能仅据熵统计认定温度就是根因。

## 同容量对照：缩小模型没有解决问题

两组都用宽64、2层Transformer、dropout0.1，共413225参数；相同初始权重、样本顺序、AdamW、batch16、24epoch、相同条件贪心标签和软CE+0.25硬CE。两卡各训练一组。固定输入组把全部提示词embedding替换为零，仍保留“已剪层集合+步数”条件。推理时它输出一个固定方案，因此是学习得到的静态对照。

真实输入组选epoch20；固定输入组选epoch12。固定方案为0-based索引 `[4, 8, 2, 10, 16, 14]`，保护层0和1不变。

| 方案 | 验证100条 KL | 未参与选checkpoint的68条 KL | 验证100条 PPL |
| --- | ---: | ---: | ---: | ---: |
| 完整OPT | 0.000000 | 0.000000 | 14.4558 |
| 旧静态：16条校准 | 0.099735 | 0.103472 | 15.8072 |
| 原动态Router：宽256 | 0.089959 | 0.093632 | 15.4332 |
| 新动态Router：宽64 | 0.096935 | 0.101193 | 15.7080 |
| 新固定输入Router：宽64、800条训练 | 0.081695 | 0.082311 | 15.3448 |
| 逐样本条件贪心搜索 | 0.053710 | 0.054123 | 15.0009 |

同容量真实输入减固定输入的KL差为0.015239，95%区间[0.005609, 0.024446]。这次小规模实验中，真实输入组更差。它相对交换方案仍无稳定优势。

原Router减新固定输入对照的KL差为0.008263，95%区间[-0.001253, 0.016884]。应按该区间判断稳定性，不能只根据均值排序。

旧宽256模型与本次宽64模型的训练分片方式不同，因此不是单独隔离宽度因素的因果实验。真正严格匹配的是本次两组宽64模型。新静态对照使用800条训练记录，旧静态仅16条校准；这提示此前静态基线偏弱，但新静态也不是全局最优剪层方案。

本轮只有一个种子，所有区间为描述性配对bootstrap，未校正文档依赖和多重比较。不能据此否定输入自适应剪层这个研究方向。

## 下一版的具体优先级

1. 保留原Router、两组小模型、旧静态与新学习静态作为对照。冻结旧测试结果；开发继续使用训练/验证，新最终测试另取独立记录。
2. 下一次标签扩展先用训练文档：在已有联合贪心前缀附近分叉，或采样Router自身前缀，完整评分剩余候选，补充第4至6步的集合条件标签。不能用本轮验证扫描结果训练。
3. 在相同容量与数据预算下比较“原贪心路径标签 / 原标签+分叉状态标签”；先只改状态覆盖。之后再单独比较原CE目标与直接约束KL差的候选排序目标，避免一次修改多个因素。
4. 若输入匹配收益仍不稳定，再扩大独立训练文档，并检查同一提示词不同续写的最优方案是否稳定。单个真实后缀的oracle差距不全是提示词可预测信息。
5. 动态方案同时优于同数据静态与交换方案后，再做双方预算一致的恢复微调及聊天/下游任务评估。当前两项新实验均已结束，没有额外大规模训练在运行。
