# 每轮提示词固定选层：协同贪心实验

本轮采用用户确认的执行语义：本轮开始时只读取完整提示词的 token 与位置 embedding，逐步选出 K=6 个跳过层；提示词 prefill 与本轮后续生成使用同一组层，保留层持续维护 KV cache。新一轮重新选层时新建缓存并重算整个上下文。现阶段只支持单请求、无 padding 的生成，不直接复用不同方案的历史缓存。

## 协同剪枝与训练

标签从空集合开始。第 s 步在已剪集合 S 上，对每个候选层 i 实际评估 S∪{i}，选联合损失最小的候选；下一步重新评估全部剩余候选，不按单层分数一次性取 top-K。保存完整候选代价、已选集合、选择次序与最终 keep mask（1=keep、0=skip）。

Router 编码提示词一次，然后把提示词表征、已选层集合和当前步骤作为条件，逐步输出下一层的代价分数，共选 6 次。较低分数表示更适合剪掉。训练监督来自上述条件贪心路径和候选联合代价，用软候选排序交叉熵与硬贪心选择交叉熵组合。这样标签生成与推理两侧都显式保留层间协同，而非独立预测每层重要性。

本阶段先训练 Router，冻结 OPT 权重。基础模型的恢复微调尚未实施；固定静态对照也不进行恢复微调，两者在此阶段使用相同的原始 OPT。若 Router 学习与泛化通过，再做动态和静态双方的数据、预算一致的恢复训练。

## 数据与目标

使用本地 C4 文件每行一条记录的结构。归档语料生成器 `legacy/prepare_dataset.py` 明确将每条流式记录清洗后写到独立一行。原始 URL、远程文档 ID 已丢失，因此“记录分组”可验证，不能声称已验证所有近重复文档独立。

准备 1,032 条不同记录：训练 800、验证 100、测试 100、静态校准 16、先导 16。每条只取一个 128-token 提示词（含 BOS）与 32-token 自然续写，不生成嵌套长度；全局排除精确记录、提示词前缀和前 32 个词相同的重复内容，再用固定 seed 579 分配 split。原阶段 1 使用的字节区间被排除，最近旧训练 token 前缀也被检查。旧特征数据的训练内容仍无法穷尽排除。

评分目标为在提示词及续写始终使用同一方案时，32 个续写预测位置的 KL(full||pruned) 平均值，float32 计算分布。对应位置从提示词最后一个 token 的输出开始，目标 token 为实际后续文本；不把提示词内部所有位置纳入优化目标。

续写只用于离线标签、训练/验证评分。Router 从接口到实际调用均仅接收 128-token 提示词 embedding，不读取未来续写。自然文本续写用于第一轮技术验证，不能代表聊天指令、完整 PIQA 或多轮任务质量。

## 推进阶段与对照

1. 先导实验：真实 OPT-13B 上验证固定路由的缓存解码与相同路由重算前缀的一致性，验证被跳层没有 K/V、保留层缓存长度完整；用 16 条独立校准记录生成静态联合贪心方案，用 16 条先导记录测量逐输入贪心与静态的差异和耗时。
2. 通过先导后，为 800 训练和 100 验证记录生成条件贪心轨迹；不生成测试集搜索标签。两张 GPU 按样本分片，K=6，每条 213 次候选联合评分。
3. 两卡 DDP 训练提示词 Router，最多 24 epoch。每卡 batch8，以固定 32 条验证记录的真实续写 KL 选择 checkpoint；测试集不用于选择。学习率和候选温度按新增训练程序预先固定。
4. 在 100 条测试记录比较完整模型、独立校准静态方案、真实提示词 Router、无固定点交换方案、固定训练提示词的 Router 输出。mask 交换保持边际分布，识别输入匹配收益。报告续写 KL、NLL/PPL、组合多样性、按记录配对 bootstrap。
5. 少量测试提示词做固定长度自由生成计时：一次热身、三次测量。Router 只在 prefill 前调用一次。分别记录 Router、prefill、decode 和总耗时，缓存实际数据字节；忽略 EOS 停止使工作量一致，报告该限制，不当作完整服务吞吐。

## 缓存数值预检与失败留存

`prompt_fixed_experiment_v1.py` 的真实模型先导在缓存数值预检阶段停止，尚未生成标签。初版除分布 KL 外额外限制所有原始 logit 的最大绝对误差≤0.125；FP16 对照中个别低概率 logit 超过此值。

独立 `probe_prompt_cache_v1.py` 对两条记录的完整/剪层模型检查：缓存与并行重算平均 KL 为约 9e-6～3.2e-5，所有下一 token argmax 一致；同时串行重算前缀，确认存在相近量级的序列形状数值差异。最大位置 KL 为约 4.84e-4；logit 最大绝对差可达 0.195。诊断记录保留于 `runs/stage3_cache_numerics_20261104_01/`。

新增 v2 保留原程序和失败记录，分布验收采用平均 KL≤1e-4、最差位置 KL≤1e-3，继续保存全部 logit 误差、argmax 一致率和缓存字节。这是依据先导数值对照调整的验收标准，不能称为逐位数值相等。小型 FP32 OPT 的缓存/并行预测、真实层执行计数、缓存方案变更拒绝、异常恢复和协同候选选择等测试通过。

## 资源、保存与发布

所有 GPU 实验通过 `run_with_resources_v2.py --gpus 1,3` 顺序启动，共 21 个 CPU 核，两个 worker 各默认 10 线程。全部旧源文件、旧模型、数据和结果不可修改。新增程序使用独立版本，输出使用新目录，模型 checkpoint 用独占写入的新名称。阶段开始时 216 个既有文本证据文件的哈希记录在 `stage3_start_baseline_20261104.json`，原始/归档文件另按原 manifest 核对。

GitHub 只上传新增程序、协议、汇总、逐步候选分数和运行日志；不上传语料、token 数组、生成 token 序列或任何模型权重。旧报告结论保留为历史记录，本协议取代其中“直接改为整段所有位置优化”的下一阶段建议。
